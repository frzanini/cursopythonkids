Como usar este caderno

  1. Leia o passo inteiro antes de digitar.
  2. Digite o código você mesmo. Copiar e colar parece mais rápido, mas é digitando que a gente aprende (e descobre os erros).
  3. Rode o programa depois de cada passo.
  4. Compare com a janelinha ao lado do passo. Ela mostra o que deve aparecer.

As linhas marcadas assim no código são as novas daquele passo. As outras você já tem.

No fim de cada fase há uma missão para marcar, um quiz rápido e desafios para quem quer ir além.

Como rodar o seu programa

Tem dois jeitos, e os dois fazem a mesma coisa:

  • Clicar no botão ▶ Run Python File, no canto superior direito do VS Code.
  • Abrir o terminal (menu Terminal > New Terminal) e digitar:
python jogo.py
Se deu certo

Abre uma janela com o seu jogo. Enquanto ela estiver aberta, o terminal fica "ocupado". Para parar, feche a janela do jogo no X.

Antes de rodar, salve com Ctrl+S. Uma bolinha branca no nome da aba quer dizer "arquivo não salvo".

Como ler uma mensagem de erro

Errar faz parte de programar. Todo programador erra várias vezes por dia. Quando algo dá errado, o Python escreve uma mensagem no terminal, mais ou menos assim:

Traceback (most recent call last):  File "jogo.py", line 12, in draw    screen.fil(COR_DE_FUNDO)AttributeError: ... has no attribute 'fil'
  • Olhe a última linha: ela diz o tipo de erro.
  • Procure line seguido de um número: é a linha do seu código onde está o problema.
  • Vá até essa linha e compare, letra por letra, com o código do caderno.

Programa, algoritmo e a ordem das coisas

Um programa é uma lista de instruções que o computador segue.

Um algoritmo é a sequência de passos para resolver um problema, como uma receita de bolo: cada passo na ordem certa.

O computador faz uma instrução de cada vez, de cima para baixo. Ele não adivinha o que você quis dizer e não pula na frente. Numa receita, trocar "leve ao forno" com "misture os ovos" estraga o bolo. No código é igual.

O esqueleto do jogo

Digite estas duas linhas no jogo.py:

import pgzrun

pgzrun.go()
  • import pgzrun traz para o seu programa um código pronto que veio de fora. É ele que dá screen, draw() e o resto do jogo. Fica sempre na primeira linha.
  • pgzrun.go() liga o motor do jogo: abre a janela e fica repetindo "desenha a tela, escuta o teclado, desenha de novo". Fica sempre na última linha.
Ideia nova · biblioteca

Você não escreveu o pgzrun. Ele vem de uma biblioteca (ou pacote): um monte de código pronto que outras pessoas escreveram para todo mundo usar. A nossa se chama Pygame Zero e foi guardada dentro do .venv no Módulo 0.

Repare: você instalou o pgzero, mas escreve import pgzrun. O pacote inteiro é o pgzero. O pgzrun é uma peça de dentro dele, a "chave de ligar" do jogo.

Tamanho e título da janela

Coloque três linhas novas entre o import e o pgzrun.go():

import pgzrun

WIDTH = 800
HEIGHT = 600
TITLE = "Crescendo como Jesus"

pgzrun.go()
Ideia nova · variável

Uma variável é um nome que guarda um valor. WIDTH = 800 quer dizer "de agora em diante, WIDTH vale 800".

  • WIDTH (largura) e HEIGHT (altura) são o tamanho da janela em pixels, os pontinhos que formam a tela.
  • TITLE é um texto, por isso fica entre aspas. Ele aparece na barra de cima da janela.
  • O Pygame Zero reconhece esses três nomes sozinho. Por isso eles precisam ser escritos assim mesmo, em letras MAIÚSCULAS.
Rode!

A janela aparece com 800 × 600 pixels e "Crescendo como Jesus" escrito na barra.

Ainda preta, mas agora com o título na barra.

Pintar o fundo

Agora vamos criar a sua primeira função. Adicione as linhas marcadas:

import pgzrun

WIDTH = 800
HEIGHT = 600
TITLE = "Crescendo como Jesus"

COR_DE_FUNDO = "skyblue"


def draw():
    screen.fill(COR_DE_FUNDO)


pgzrun.go()
Ideia nova · função

Uma função é um pedaço de código com nome, guardado para rodar quando alguém chamar. def cria a função, depois vem o nome (draw), e os () e os : no fim são obrigatórios.

A draw() é especial: o Pygame Zero chama ela sozinho, várias vezes por segundo, sempre que precisa redesenhar a tela. Você só escreve o que desenhar.

Atenção ao recuo

A linha screen.fill(...) começa um pouco para dentro. Esse espaço se chama indentação, e no Python ele é regra: é ele que diz "esta linha faz parte da função draw". Se faltar, dá IndentationError. Depois de uma linha que termina em :, o VS Code recua a próxima sozinho quando você aperta Enter.

screen.fill(COR_DE_FUNDO) pinta a tela inteira com a cor guardada na variável.

Rode!

A janela aparece pintada de azul-céu. Depois troque "skyblue" por "darkgreen", "purple" ou "orange" e rode de novo. Também dá para usar números de cor, como (255, 0, 0) para vermelho.

A tela inteira em azul-céu.

4

A mensagem de boas-vindas

Crie a variável COR_DO_TEXTO e, dentro de draw(), depois do screen.fill, desenhe um texto:

import pgzrun

WIDTH = 800
HEIGHT = 600
TITLE = "Crescendo como Jesus"

COR_DE_FUNDO = "skyblue"
COR_DO_TEXTO = "white"


def draw():
    screen.fill(COR_DE_FUNDO)
    screen.draw.text(
        "Bem-vindo(a) ao " + TITLE + "!",
        center=(WIDTH // 2, HEIGHT // 2),
        fontsize=40,
        color=COR_DO_TEXTO,
    )


pgzrun.go()
  • "Bem-vindo(a) ao " + TITLE + "!" é o texto. O + junta textos: o pedaço fixo, mais o que está guardado em TITLE, mais "!".
  • center=(WIDTH // 2, HEIGHT // 2) é o ponto onde o texto fica centralizado. O // é a divisão inteira: 800 // 2 dá 400, o meio da largura.
  • fontsize=40 é o tamanho da letra, e color=COR_DO_TEXTO é a cor.
Rode!

A mensagem "Bem-vindo(a) ao Crescendo como Jesus!" aparece em branco, no meio da tela.

O texto fica bem no centro: x = 400, y = 300.

1

Coordenadas e o personagem

Ideia nova · coordenadas

Todo lugar da tela tem um endereço: um par de números (x, y). O x cresce para a direita. O y cresce para baixo. O (0, 0) é o canto superior esquerdo. É diferente do caderno de matemática, onde o y cresce para cima!

Passe o mouse (ou toque) na janelinha ao lado para ver as coordenadas.

Crie as variáveis do personagem antes de draw(), e troque o que está dentro de draw(). O seu arquivo inteiro fica assim:

import pgzrun

WIDTH = 800
HEIGHT = 600
TITLE = "Crescendo como Jesus"

COR_DE_FUNDO = "skyblue"
COR_DO_TEXTO = "white"
NOME_DO_PECADOR = "Escreva seu nome aqui"

# Posição e tamanho do personagem (um círculo, por enquanto)
personagem_x = WIDTH // 2
personagem_y = HEIGHT // 2 - 60
personagem_raio = 40
personagem_cor = "gold"


def draw():
    screen.fill(COR_DE_FUNDO)

    screen.draw.text(
        "Pecador: " + NOME_DO_PECADOR,
        topleft=(10, HEIGHT - 30),
        fontsize=16,
        color=COR_DO_TEXTO,
    )

    screen.draw.filled_circle(
        (personagem_x, personagem_y), personagem_raio, personagem_cor
    )


pgzrun.go()
  • WIDTH // 2 é o meio da largura. O - 60 no y sobe o personagem um pouco, para sobrar espaço para a pergunta.
  • screen.draw.filled_circle((x, y), raio, cor) desenha um círculo cheio: o centro, o tamanho (raio) e a cor.
  • topleft=(10, HEIGHT - 30) é outro jeito de posicionar texto. Em vez de centralizar, ele prende o canto superior esquerdo do texto nesse ponto: 10 pixels da borda esquerda, perto do rodapé.
Rode!

Aparece uma bola dourada um pouco acima do centro, e "Pecador: [seu nome]" pequeno no canto de baixo.

Os botões Sim e Não

Junto das outras variáveis, crie os dois botões:

# Área (retângulo) de cada botão: (x, y) do canto e (largura, altura)
botao_sim = Rect((WIDTH // 2 - 160, HEIGHT // 2 + 120), (120, 50))
botao_nao = Rect((WIDTH // 2 + 40, HEIGHT // 2 + 120), (120, 50))
  • Rect((x, y), (largura, altura)) é um retângulo. O primeiro par é o canto superior esquerdo; o segundo é o tamanho. O Pygame Zero já conhece o Rect, não precisa de outro import.
  • Por enquanto cada botão é só uma área invisível. Agora vamos pintá-la.

No fim de draw(), depois do personagem, acrescente:

    screen.draw.filled_rect(botao_sim, "green")
    screen.draw.text("Sim", center=botao_sim.center, fontsize=28, color="white")

    screen.draw.filled_rect(botao_nao, "red")
    screen.draw.text("Não", center=botao_nao.center, fontsize=28, color="white")
  • screen.draw.filled_rect(retangulo, cor) pinta o retângulo.
  • botao_sim.center é um atalho: o próprio Rect calcula o ponto do meio dele. Você não precisa fazer conta.
Rode!

Aparecem um botão verde "Sim" e um vermelho "Não" embaixo do personagem. Clicar ainda não faz nada.

4

Descobrindo o clique

Depois de draw() (fora dela, sem recuo), crie uma nova função:

def on_mouse_down(pos):
    if botao_sim.collidepoint(pos):
        print("clicou no Sim")
    elif botao_nao.collidepoint(pos):
        print("clicou no Não")
Ideia nova · evento

Um evento é algo que acontece durante o jogo, como um clique. A on_mouse_down(pos) é especial, como a draw(): o Pygame Zero chama ela sozinho toda vez que você clica na janela, e coloca em pos o (x, y) do clique.

Ideia nova · decisão

if quer dizer "se", e elif quer dizer "senão, se". Se o clique caiu dentro do botão Sim, faz uma coisa. Senão, se caiu no Não, faz outra. Não esqueça os : no fim dessas linhas.

botao_sim.collidepoint(pos) responde True (verdadeiro) ou False (falso) para a pergunta "este ponto está dentro do retângulo?".

print(...) escreve uma mensagem no terminal do VS Code, não na janela do jogo.

Rode!

Nada muda na janela. Mas olhe o terminal: a cada clique num botão aparece clicou no Sim ou clicou no Não. Clicar fora dos botões não escreve nada.

5

O personagem reage

Agora o clique vai mudar o personagem de verdade. Junto das outras variáveis, lá em cima, crie:

# Estado da resposta: começa sem nenhuma resposta ainda
respondeu = False
resposta_foi_sim = False

True e False são os únicos dois valores lógicos do Python. Aqui eles guardam "o jogador já respondeu?" e "a resposta foi Sim?".

Agora troque a on_mouse_down inteira por esta:

def on_mouse_down(pos):
    global respondeu, resposta_foi_sim, personagem_raio, personagem_cor

    if botao_sim.collidepoint(pos):
        respondeu = True
        resposta_foi_sim = True
        personagem_raio = 60
        personagem_cor = "yellow"
    elif botao_nao.collidepoint(pos):
        respondeu = True
        resposta_foi_sim = False
        personagem_raio = 30
        personagem_cor = "gray"
Por que o global?

Uma função pode ler as variáveis de fora dela, mas não pode mudá-las sozinha. A linha global avisa o Python: "estas variáveis não são novas, são as lá de cima, e eu quero mudá-las de verdade". Sem o global, a tela nunca muda.

Rode!

Clique em Sim: o personagem cresce e fica amarelo. Feche, rode de novo e clique em Não: ele encolhe e fica cinza.

Clique nos botões da janelinha para ver como deve ficar.

6

Uma mensagem para cada resposta

No fim de draw(), depois dos botões, acrescente:

    if respondeu:
        if resposta_foi_sim:
            mensagem = "Muito bem! Continue assim!"
        else:
            mensagem = "Que tal fazer isso hoje?"

        screen.draw.text(
            mensagem,
            center=(WIDTH // 2, HEIGHT // 2 + 220),
            fontsize=26,
            color=COR_DO_TEXTO,
        )
  • O primeiro if respondeu: só deixa entrar depois que um botão foi clicado. Antes disso, respondeu é False e nada aparece.
  • O if/else de dentro escolhe qual texto mostrar. else quer dizer "senão".
  • Repare nos recuos: o if de dentro tem mais recuo, porque está dentro do primeiro if.
= ou ==?

= guarda um valor numa variável: respondeu = True. == compara dois valores e responde True ou False: 2 == 2 dá True. São coisas diferentes, e trocar um pelo outro é um dos erros mais comuns.

O laço do jogo

O Pygame Zero fica repetindo duas coisas, umas 60 vezes por segundo: primeiro ele chama update() para pensar e mudar as coisas de lugar, depois chama draw() para desenhar. Como cada volta move o personagem só um pouquinho, o seu olho vê um movimento suave, como num desenho animado.

1

Limpar a cena e pôr o personagem no meio

Apague do seu jogo.py:

  • a variável PERGUNTA;
  • os botões botao_sim e botao_nao;
  • as variáveis respondeu e resposta_foi_sim;
  • a função on_mouse_down inteira;
  • dentro de draw(): a pergunta, os botões e a mensagem final.

Depois tire o - 60 do personagem_y, crie a VELOCIDADE e coloque uma dica no topo da tela. O arquivo inteiro fica assim:

A função update() e o primeiro movimento

Depois de draw() (fora dela, sem recuo), crie:

def update():
    global personagem_x, personagem_y

    personagem_x = personagem_x + VELOCIDADE
  • update() é outra função especial. O Pygame Zero chama ela sozinho, umas 60 vezes por segundo, sempre antes de desenhar.
  • O global é o mesmo da Fase 2: sem ele, a função não consegue mudar as variáveis de fora.
Ideia nova · x = x + 5

personagem_x = personagem_x + VELOCIDADE não é uma conta de matemática. É uma ordem: "pegue o valor que está em personagem_x agora, some VELOCIDADE e guarde de volta". Se personagem_x vale 400, depois dessa linha vale 405. Na próxima volta, 410. Depois 415...

Rode!

A bola desliza sozinha para a direita e some pela borda. É para ser assim mesmo. No próximo passo você pega o controle.

personagem_x = 400

3

Andar só quando a seta está apertada

Troque a linha do personagem_x por dois if que olham o teclado:

def update():
    global personagem_x, personagem_y

    if keyboard.right:
        personagem_x = personagem_x + VELOCIDADE
    if keyboard.left:
        personagem_x = personagem_x - VELOCIDADE
  • keyboard.right vale True enquanto a seta → está apertada, e False quando você solta. Como o update() roda o tempo todo, o jogo pergunta "a seta está apertada agora?" 60 vezes por segundo.
  • keyboard.left diminui o x, e o personagem vai para a esquerda.
  • São dois if separados, e não um elif. Se você apertar as duas setas juntas, as duas linhas rodam e o personagem fica parado.
Rode!

A bola fica parada até você segurar →. Soltou, ela para. Com ← ela vai para a esquerda.

Lembrete

Primeiro clique na janela do jogo para ela receber as teclas. Se o VS Code estiver selecionado, as setas vão para o editor.

4

As quatro direções

Acrescente cima e baixo dentro do update():

def update():
    global personagem_x, personagem_y

    if keyboard.right:
        personagem_x = personagem_x + VELOCIDADE
    if keyboard.left:
        personagem_x = personagem_x - VELOCIDADE
    if keyboard.down:
        personagem_y = personagem_y + VELOCIDADE
    if keyboard.up:
        personagem_y = personagem_y - VELOCIDADE

Lembra da Fase 2? O y cresce para baixo. Então descer é + VELOCIDADE e subir é - VELOCIDADE.

Rode!

O personagem anda nas 4 direções. Segurando duas setas juntas (→ e ↑, por exemplo), ele anda na diagonal.

Clique na janelinha e use as setas do seu teclado (ou os botões). Veja os valores mudando.

5

Voltar ao meio com a barra de espaço

Depois do update() (fora dele, sem recuo), crie:

def on_key_down(key):
    global personagem_x, personagem_y

    if key == keys.SPACE:
        personagem_x = WIDTH // 2
        personagem_y = HEIGHT // 2
  • on_key_down(key) é a prima de teclado da on_mouse_down(pos). O Pygame Zero chama ela uma vez, no instante em que você aperta uma tecla, e key diz qual tecla foi.
  • keys.SPACE é o nome que o Pygame Zero dá para a barra de espaço. Também existem keys.A, keys.LEFT, keys.RETURN (o Enter)...
  • Aqui aparece o == da Fase 2: "a tecla apertada é igual ao espaço?".
keyboard ou on_key_down?

Use keyboard.right dentro do update() para coisas que acontecem enquanto a tecla está apertada, como andar. Use on_key_down para coisas que acontecem uma vez quando a tecla desce, como voltar ao meio.

Rode!

Ande para longe com as setas e aperte a barra de espaço: o personagem volta para o centro na hora.
